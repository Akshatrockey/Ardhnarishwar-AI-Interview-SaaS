1. Executive Summary & Strategic Vision

Ardhnarishwar AI SaaS is an enterprise-grade, multi-tenant B2B AI talent assessment and Human Resource Management System (HRMS). Multi-Tenant Logical Partitioning Strategy

Tenant isolation is enforced through the Zero-Trust Logical Query Scoping Pattern:

  • Mandatory Foreign Key Indexing: Every relational business entity (jobs, candidates, interview_sessions, audit_logs) includes an indexed company_id foreign key column.
  • Anti-Header Spoofing: The backend completely disregards client-supplied headers (such as X-Company-ID or X-Tenant-Tag). The tenant context is extracted exclusively from cryptographically verified claims within the signed JWT payload.
  • Cascading ORM Deletions: Organizational teardowns automatically and cleanly cascade deletions across rounds, question bindings, sessions, answers, and scorecards, leaving zero orphaned records.
  • Dual-Engine Resilience: The application automatically connects to enterprise MySQL 8.0 on startup, with seamless fallback to an embedded SQLite database (ardhnarishwar_local.db) if external database clusters undergo maintenance.

4. In-House Core-AI Evaluation Engine & Formulations

The Ardhnarishwar Core-AI Evaluation Engine is engineered to execute deterministically without relying on third-party generative APIs. The engine blends Vector Space Modeling, Concept Graph Traversal, STAR Behavioral Heuristics, and Speech Fluency Metrics into an explainable scoring pipeline.

4.1 Mathematical Formulations

1. Multi-Gram TF-IDF Vectorizer & Cosine Similarity

Candidate speech transcripts $d$ and administrator predefined golden answers $r$ are vectorized across unigrams and bigrams ($n \in [1, 2]$). Term frequency and inverse document frequency are calculated as: 

  TF(t, d) = f(t, d) / ∑_{t' ∈ d} f(t', d)
  IDF(t, D) = ln((1 + |D|) / (1 + |{d ∈ D : t ∈ d}|)) + 1
  CosineSimilarity(u, v) = (u · v) / (||u||₂ · ||v||₂)

2. Concept Graph Traversal & Anti-Pattern Penalties

Questions are bound to a directed acyclic concept graph $G = (V, E)$ where nodes represent required technical terms and anti-pattern nodes represent disqualifying misconceptions: 

  ConceptScore = (∑_{c ∈ V_matched} Weight(c)) / (∑_{c ∈ V_total} Weight(c)) * 100
  AntiPatternDeduction = ∑_{a ∈ A_detected} Penalty(a)
  NetTechnicalScore = Max(0, (w₁ · CosineSimilarity + w₂ · ConceptScore) - AntiPatternDeduction)

3. STAR Methodology Behavioral Heuristic

For behavioral and leadership questions, the candidate response is evaluated across the four phases of the STAR framework (Situation, Task, Action, Result) using heuristic regex boundary markers and lexical indicators: 

  STAR_Score = 0.25 · Score(Situation) + 0.25 · Score(Task) + 0.25 · Score(Action) + 0.25 · Score(Result)

4. Speech Fluency & Words-Per-Minute (WPM) Normalization

Transcribed speech duration $T$ (seconds) and word count $W$ yield the cadence velocity: 

  WPM = (W / T) * 60
  FluencyMultiplier = 1.0 - (|WPM - WPM_optimal| / 100) * HesitationFactor

4.2 Model Versioning Registry & Reproducibility Hashes

Every AI evaluation generated by the platform is cryptographically bound to an active AI model snapshot. If a hiring decision is audited months or years later, the exact original score can be reproduced deterministically.

Instead of static QR codes that employees can photograph and share, the portal generates a cryptographic 6-digit Time-Based One-Time Password (TOTP) that cycles every 30 seconds based on HMAC-SHA256 and UNIX epoch time.

Uses the HTML5 Geolocation API to capture latitude, longitude, and device accuracy. The punch is accepted only if the candidate is physically within the authorized facility radius (e.g., 100 meters).

9. Zero-Trust Security Architecture & Audit Immutability

Security within Ardhnarishwar AI SaaS is designed under a Zero-Trust posture where every network request, query parameter, and authorization credential is strictly validated before execution.

🛡️ Zero-Trust JWT Authentication

Uses HMAC-SHA256 encrypted tokens with strict claim resolution. Role escalation, token expiration, and forged tenant claims are blocked at the ASGI middleware layer.

🛑 Anti-Header Spoofing Guard

Prevents malicious tenant crossing. The API completely ignores untrusted client headers (e.g. X-Tenant-Id) and scopes all DB queries via jwt.company_id.

Immutable Audit Logging Architecture

Compliance and accountability are guaranteed by the platform's Append-Only Immutable Audit Log Architecture:

  • WORM (Write Once, Read Many) Principle: The database permissions explicitly prohibit UPDATE and DELETE statements on the audit_logs table. Any attempted modification generates an immediate security alarm.
  • Structured Severity Indexing: Events are cataloged by severity (INFO, WARNING, CRITICAL) with client IP address, user-agent, target resource, and JSON delta payloads.
  • Dual-Tier Retention: Hot tier logs reside in the active database for 90 days with composite indexing on (company_id, created_at). Cold tier archival exports batched logs to encrypted object storage vaults.
